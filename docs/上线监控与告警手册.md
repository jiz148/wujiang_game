# 上线监控与告警手册

## 1. 范围

本手册定义 P7.5.3 的单进程可观测基线。它用于判断进程存活、依赖就绪、HTTP 错误/慢请求/限流压力，不代替 P7.5.4 的外部指标采集、持久化日志、通知渠道和正式部署演练。

## 2. 健康端点

- `GET /api/health/live`：只回答当前 HTTP 进程是否能处理请求。成功返回 200、`status=ok` 和进程运行时间；不访问业务数据库。负载均衡器可用它判断进程是否需要重启。
- `GET /api/health/ready`：初始化并读取账号、分析、战绩和战略四个 SQLite 关键表。全部正常返回 200、`status=ready`；任一失败返回 503 和脱敏的 `failed`，不返回路径、SQL 或异常文本。战略维护门禁生效时必须为未就绪。
- 两个端点都公开且不包含个人/战役数据；所有响应都带 `X-Request-ID` 和安全头。

## 3. 结构化请求日志

生产默认向标准输出每请求写一行 JSON；开发/测试默认关闭。可用 `WUJIANG_REQUEST_LOGS=true|false` 显式覆盖。

允许字段只有：UTC 时间、级别、事件名、服务端生成的请求 ID、HTTP 方法、白名单路由模板、状态码、耗时和限流分类。查询串、未知 URL 片段、客户端 IP、请求/响应载荷、密码、session token、房间 token、加入码、账号名和玩家自由文本不得进入日志。未知 API 路径统一折叠为 `:unknown`。日志输出失败不得中断玩家请求。

## 4. 指标端点与授权

`GET /api/metrics` 返回进程运行时间、请求总数/在途数、状态码大类、每方法+路由模板的请求/服务端错误/限流/慢请求数、平均/最大耗时、五分钟窗口和当前告警。不按账号、IP、战役、房间或任意载荷建立标签。

- 开发/测试环境可直接读取。
- 生产必须配置至少 16 字符的 `WUJIANG_OPS_TOKEN`，并以 `X-Wujiang-Ops-Token` 提供。未配置、缺失或错误均拒绝；运维 token 不进入指标或日志。
- 当前计数器仅在单进程内存中，最近窗口最多保存 10,000 个脱敏结果；重启清零。P7.5.4 必须由外部系统定期采集并持久化。

## 5. 告警基线

| 告警 | 默认阈值 | 级别 | 首要处置 |
| --- | --- | --- | --- |
| `dependency_not_ready` | 最近就绪检查任一依赖失败 | critical | 立即摘除流量；检查维护标记、磁盘、权限和 SQLite，必要时按故障手册停服诊断 |
| `elevated_server_error_rate` | 5 分钟至少 20 请求且 5xx 比例 ≥ 10% | critical | 按请求 ID 和路由模板定位；检查就绪状态，停止发版并评估回滚 |
| `sustained_slow_requests` | 5 分钟内至少 5 个耗时 ≥ 1500 ms | warning | 查看慢路由、同期就绪和磁盘/CPU；避免立即重试导致放大 |
| `rate_limit_pressure` | 5 分钟内至少 20 个 429 | warning | 确认受限分类和客户端版本；先排查攻击/重试风暴，不盲目提升额度 |

`WUJIANG_SLOW_REQUEST_MS` 可调整单请求慢阈值，默认 1500 ms。其余阈值作为当前产品基线固定，必须结合正式压测和真实多人战役再校准。

## 6. 基本故障顺序

1. 先看 live；live 失败则重启或替换进程。
2. live 成功再看 ready；ready 失败时摘除流量，不得用重启循环代替数据诊断。
3. ready 成功再看告警和路由聚合指标，用 `X-Request-ID` 关联结构化日志。
4. 涉及战略数据不一致、审计链或备份时，切换到 [战略数据故障处理手册.md](C:/Users/jiz14/TeamGH/wujiang_game/docs/战略数据故障处理手册.md)，不在在线进程内直接修库。
