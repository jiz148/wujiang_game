# 正式部署与回滚手册

## 当前默认：本地 Docker 部署

当前产品阶段只要求本地 Docker 部署。运行：

```powershell
docker compose -f compose.local.yml up -d --build
```

启动后访问 `http://127.0.0.1:8000`。端口仅绑定本机回环地址，不会向局域网或公网开放；SQLite、备份和回放保存在 `wujiang_local_data`、`wujiang_local_replays` 命名卷中。如果 8000 已被占用，可在 PowerShell 中先运行 `$env:WUJIANG_LOCAL_PORT='8001'`，再执行启动命令并访问 `http://127.0.0.1:8001`。停止服务使用：

```powershell
docker compose -f compose.local.yml down
```

不要附加 `-v`，否则会删除本地持久数据。下文公网 HTTPS 部署方法继续保留，未来明确需要公网发布时再执行。

## 部署契约

正式环境使用 `compose.production.yml`。Caddy 是唯一对外入口，负责域名证书和 HTTPS；应用容器只在固定私网提供 8000，不发布到宿主机。应用以 UID/GID 10001 非 root 运行，根文件系统只读，去除 Linux capabilities，仅 `/app/var`、`/app/replays` 和限额 `/tmp` 可写。

当前架构只允许 **1 个应用副本**。SQLite、内存房间、限流和进程指标不支持无共享状态的水平扩容。

## 上线前准备

1. 准备可持久保存 Docker volume 的 Linux 主机，安装 Docker Engine 和 Compose v2。放行 TCP 80/443 及 UDP 443，不放行 8000。
2. 将正式域名 A/AAAA 记录指向主机。Caddy 需要 80/443 以签发和续期证书。
3. 复制 `.env.production.example` 为不入库的 `.env.production`，替换域名，并生成至少 32 个随机字符的 `WUJIANG_OPS_TOKEN`。启动预检会拒绝短 token 和示例占位值。
4. 迁移现有服务时，先停服、建立手工备份并完成隔离恢复演练，再将完整 `var` 与 `replays` 导入持久卷。

## 构建与启动

```powershell
docker compose --env-file .env.production -f compose.production.yml config --quiet
docker compose --env-file .env.production -f compose.production.yml build --pull
docker compose --env-file .env.production -f compose.production.yml up -d
```

应用在监听前强制验证：生产环境、HTTPS 公网根地址、精确 Origin、关闭查询令牌、非空可信代理、开启结构化日志以及非占位的 16+ 字符运维 token。

## 发布门禁

1. 检查 `https://<domain>/api/health/live` 和 `/api/health/ready`。
2. 在 app 容器中运行 `python -m wujiang.tools.strategy_backup --db /app/var/wujiang.sqlite3 --backup-dir /app/var/backups create --reason pre-release`。
3. 在 app 容器中运行 `python -m wujiang.tools.production_audit --public-base-url https://<domain> --auth-db /app/var/wujiang.sqlite3 --analytics-db /app/var/analytics.sqlite3 --match-history-db /app/var/match-history.sqlite3 --strategy-db /app/var/wujiang.sqlite3 --backup-dir /app/var/backups --replay-dir /app/replays`。
4. 审计必须是 `status=passed`、critical=0、warning=0，且最新备份隔离恢复演练为 passed。

审计检查生产配置、四个数据依赖、session 只存摘要、分析/战绩/操作审计/回放无凭据字段、战略诊断、备份清单/摘要和恢复演练。输出不回显原始秘密。

## 更新与回滚

1. 更新前建立并演练手工备份，记录旧镜像摘要。
2. 使用不可变版本标签构建新镜像，更新 app 容器时保留命名卷。
3. 验证 live/ready、原账号登录、战役列表/进入、备份和完整生产审计。
4. 代码回滚使用旧镜像，不删除 volume。如果新版已执行不兼容数据迁移，停服并按 [战略数据故障处理手册.md](C:/Users/jiz14/TeamGH/wujiang_game/docs/战略数据故障处理手册.md) 使用发布前备份整库恢复。
5. 禁止在故障处理中运行 `docker compose down -v`，该命令会删除正式数据卷。

## 日常运维

- app 对 SIGTERM 执行 HTTP shutdown，容器停止容忍时间为 30 秒。
- 备份必须定期复制到与主机/卷不同的故障域；容器内备份不等于异地备份。
- 每次发布、每月及重大战役前至少运行一次生产审计与恢复演练。
- 日志、指标与告警处置见 [上线监控与告警手册.md](C:/Users/jiz14/TeamGH/wujiang_game/docs/上线监控与告警手册.md)。
