## 2. 实施顺序

### H0：流水线与首批试运行

- 建立本文、路线图 Phase H、武将规则索引与批次记录。
- 首批：`excel_r138` 无名信使、`excel_r327` 红莲魔。盖泽尔。
- 目标：验证不新增复杂前端选格模式时，规则、实现、AI、测试、审计和文档能形成稳定闭环。

### H1：低歧义批次

- 优先条件：全部能力可复用通用实现或既有钩子；没有未回答问题；没有新的跨单位选择协议。
- 常规批次 6～8 名；若同批共享机制，可适当合并。
- 每批结束后更新“当前进度”、武将说明、规则索引和项目地图。

### H2：中等复杂批次

- 范围：自定义范围、计数点、开关、持续状态、召唤物、天气和局部场地等局部扩展。
- 每批 3～5 名，以共享机制为分组依据，而不是只按源表行号推进。

### H3：引擎依赖批次

- 范围：新的多阶段选择、复杂复制/操控、特殊连锁窗口、回合插入和跨单位资源。
- 先形成通用引擎契约与行为测试，再接入使用该机制的全部武将。
- 每次引擎扩展必须保持现有武将和前端协议兼容。

### H4：收口与全量验收

- 清零特殊技能/特性静默未映射项和未实现代码列表。
- 复核 388 名公开资料、选将、战斗创建、AI、战略动态读取和回放公开状态。
- 完成全量回归与最终 388/388 清单签收。

## 3. 单名武将完成定义

每名武将必须同时完成：

1. **规则**：源表文本、问题清单答案和持久规则已写入《武将说明》，无未解释片段。
2. **战斗实现**：技能、特性、数值、资源、次数、冷却、时机、目标和持续时间均真实结算。
3. **前端**：行动入口、合法目标、预览、资源与公开状态可见；需要选择时桌面和手机都能完成。
4. **AI**：AI 能生成合法 payload，能判断核心能力价值，不会因新能力空转或卡死。
5. **定向测试定义**：覆盖正常路径、限制条件、边界、护盾/回避/魔免/连锁等适用交互；用例由开发代理编写，但所有会推进回合的执行统一并入用户运行的总测试。
6. **行为测试定义**：至少一条玩家视角完整场景覆盖主要机制；同样只由总测试统一执行。
7. **设计思想档案**：在 Excel 的“武将设计思想”工作表写明定位、设计意图、操作顺序、AI 原则、通用 AI 启发、预期信号与风险反模式，并同步机器可读基线。
8. **AI 深度审计**：该武将至少运行 10 场自动对局，逐场记录动作候选、状态变化、技能覆盖与具体日志；缺陷修复后重新审计。
9. **人工设计对照**：按审计报告逐项比较实现、AI 行为和设计思想，不以“没有报错”代替机制正确；逐将签收。
10. **全量回归与索引**：完整测试通过，文档和项目技能索引同步。

## 4. 批次质量门槛

固定顺序为：每批默认3名分别读取源规则 → 独立推演并锁定各自设计基线 → 逐将审查战斗/前端/专属及通用AI → 补必要测试用例、修正并做静态检查 → 更新检查修改进度 → 直接进入下一批。全部已开发武将完成后统一测试，再按结果修复和签收。逐将设计与证据标准不变，取消中途测试等待。

2026-09-06用户明确要求每次不用测试，优先改完所有已开发武将和AI后一起测试。开发代理不运行动态测试，也不逐批要求用户复跑；只保留必要用例及静态检查。全部73名检查修改完成后再使用 `python detail_test_all_wujiangs.py` 统一执行常规测试和全公开池AI对局。`--current`仅保留为用户主动要求的定向诊断入口。历史暂停/逐批签收门槛已被本段覆盖，未开发武将不在本轮范围。

任何一步失败时，本批保持“进行中”，不增加完整开发计数。问题清单已有答案直接采用；出现未覆盖且会实质改变玩法的新歧义时，不再暂停询问用户，而是根据原文、通用规则、武将定位、技能协同与反制空间作出最连贯的设计推断，并记录采用结论、放弃方案、证据、置信度和玩法后果。严禁从现有代码或测试倒推设计。

## 6. 风险控制

- 不把只有资料注册、通用片段部分可用的武将标记为完成。
- 不为赶数量绕过玩家选择、连锁窗口、护盾、回避、魔免或 AI 合法性。
- 不修改由其他开发者负责的战略功能；新增武将只沿已有动态注册接口接入。
- 不以自动化对局代替平衡结论。AI 审计用于发现规则与行动缺陷，胜率只作为后续平衡输入。
