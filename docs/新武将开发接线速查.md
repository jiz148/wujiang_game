# 新武将开发接线速查

这页是当前 OOP 结构的新将入口索引。常规新将先读本页、待开发顺序和该将源文/设计档，再按实际机制打开对应对象；无需每次通读《架构分层说明》。涉及新共享接口、对象归属不清或调用链变化时，再读架构文档的相关章节并追踪实际调用者。

## 开始前

1. 按《未实现武将开发顺序》确定精确行号，运行 `python tools/new_hero_context.py excel_rNNN` 一次读取源身份、原句、保存答案、设计状态与公开计数；再用 `python tools/check_new_hero_candidates.py excel_rNNN` 作未公开门禁。已公开将不重复新增。
2. 只依据 `excel_roster_data.py` 的源行、通用规则、已保存问卷答案，先锁 `武将设计思想.json`、`武将说明.md`，再把设计同步到 `武将实现问题清单.xlsx`。此时不要用已有实现或测试反推设计。
3. 把源文拆为声明与选取、费用与次数、命中与连锁、状态/死亡/复出、AI 决策、网页选择和可观察日志。只打开本将需要的现有对象与共享接口。

## 代码归属与调用路径

R046/R051接线补充：用户把新将技能明确等同于已有技能时，继承已有技能对象并只改显示名；不要按名字附加新效果。`front_rectangle_patterns(width=2)`当前会产生三格宽，真正宽2深3要给本将对象精确六格几何。召两只坐骑沿已有多格选格协议，`can_use`先核足两个落格；骑乘靠正常移动重合，坐骑的`on_any_turn_start`给当前骑手回魔。条件式普通移动加速使用`BattleComponent.normal_move_destination_allowed`、`normal_move_bonus_path`和`normal_move_path_allowed`，让玩家预览、正式行动及AI共用同一条路线资格；普通速内的路线仍按原规则。改共享战斗对象后只核受影响的预测契约，原本指纹过期的其他脏模块不得直接重签。

R380接线补充：需要选效果并可选单位的技能用`preview.selection.mode="option"`，对象给出`options`及每个受体的`options_by_target`，网页完成选择时提交`option_code`和`target_unit_id`；简单、倾向、标准AI均取对象的完整候选。全场非伤害技能也要由`get_target_units_for_payload`列出声明时受体，敌方才能连锁；结算时逐个走`validate_target`，不要直接加状态。永久改种族调用`Unit.change_race_permanently`，临时种族状态用`on_permanent_race_changed`调整最终恢复值。

R160接线补充：敌方进攻轮结束可选的随时技能由技能对象的`on_before_any_turn_end`开放`optional_skill_use`提示；玩家的使用/放弃经现有选择回放，AI由对象的`ai_optional_choice_score`决定。只在该窗口允许`can_use`，实际使用仍由技能对象支付资源并执行。技能效果若要重置既有属性变化而保留状态其他规则，可把归源状态放在现有状态之后，新得到的状态继续正常生效。公开骰子的多段伤害在直接AI连锁试算中必须用每击出现概率，不得重掷现场随机。

自定义位移技能继承`DashMoveSkill`并换了新代码时，标准AI可能仍按目标格技能要求“命中敌人”。技能对象须声明`ai_enemy_impact_requirement = False`并提供合法落格的`ai_payload_value`；定向场景应验证简单、倾向、标准AI均给出真正有收益的落格。R077六格飞跃为参考。

常用主路径：`registry.create_battle` 建本体 → `excel_roster` 按 kit 装配 → `Battle` 生成行动预览和声明 → 对象执行/排队效果 → 三路 AI 从同一预览造合法载荷并调用对象评分 → 网页消费同一选择协议。沿这条路径只查当前将涉及的节点；共享结构改动要记录责任对象、调用者和场景覆盖。

## 交付前的短检查

- 友军普攻支援要明确排除普攻自己，测试正式目标资格、效果入口和标准/简单/倾向三路AI；`create_battle`已启动首轮，额外调用`start_current_turn`会再次触发自动效果，夹具要按增量断言。自动召唤免费和主动召唤付费应保留两条资源路径。审计高信号须先核触发者，不能把对手武将的动作错误算在新将身上。

- 同名技能若源文不同，先核各自行号，不借其他将的额外位移/几何；R055「一闪」与R215不同。伤害“尝试”计资源时用声明时敌方占格，不能拿实际扣血替代；面积召唤的“没有单位”要核整片所选范围。召唤物给出的免费反应次数放在其自己的技能对象上。
- 审计若报告某技能“可用”却没有足够合法选格，检查技能对象的`can_use`是否覆盖最少选格数；R049的三分身在仅余两格时已提前禁用。
- 技能继承后若改了公开`code`，标准AI的“候选是否有效”过滤可能仍按旧代码表识别；先让技能对象声明适用的正收益规则，再在真实候选列表中检查正分，不能只测技能自己的评分。审计档`action_codes_to_observe`必须与最终公开代码一致；R134飞跃（大）沿用`fly_leap`，误写`big_fly_leap`会虚报缺技能。
- 已完成的有界对局后若只补了定向场景，单独运行新增定向即可；不要为更新回归数量盲用审计`--resume`，代码指纹变化会重放全部长局。若游戏行为确实变动，只重审受影响的武将。
- 新模块与 kit：`python tools/check_local_import_symbols.py <hero.py> <kit.py>`。
- 定向类：`python tools/check_focused_test_symbols.py <NewBatch...BehaviorTests>`；再做 `compileall`、JS 语法检查（若改网页）、JSON 解析和 `git diff --check`。助手随后只运行该将短定向 `python -m unittest discover -s tests -p test_behavior.py -v -k <NewBatch...BehaviorTests>` 及单将有界长AI审计，直接修错并读取审计摘要。**永不由助手运行全库测试或整份巨大行为测试文件**；若需要全库验证，把原因和命令交给用户。
- **测试夹具先核实际棋盘尺寸。** `Battle()` 默认 8×8；`registry.create_battle` 的标准棋盘由双方阵容决定。形状的名义大小不等于棋边裁切后的格数。对 11×11 等范围，断言“名义格集合 ∩ 当前棋盘”，同时在足够大的棋盘覆盖完整 121 格；不要在默认夹具上硬写 121。
- 写新将定向前先查引擎实际名称：射程属性是`attack_range`，声明动作接口为`battle.build_queued_action(payload)`；误写`range`或多传`actor`只会制造可在首轮避免的短测失败。位置固定的范围技能在`queued_payload_metadata`保存原格，并在声明层明确`ignores_shield_for_payload`/`ignores_magic_immunity_for_payload`，实际附效落到伤害返回的受体。
- 核对预览与实际载荷、参数名与必填字段、导入符号、合法目标和落格、AI 实际入口、计数/冷却不因复出刷新。若用户专场失败，先从报告目录读完整日志，修当前批次，不开启下一批。
- 破魔范围技除了结算时 `DamageContext.ignore_shield`，还要由技能对象的 `ignores_shield_for_payload` 在声明时公开穿盾；只改伤害层会把被普通盾保护但仍会受影响的对方单位错误地排除出连锁窗口。超过64个区域候选时，在首次长局前补第65项之后仍有收益的正式AI场景。
- 专场失败时先运行 `python tools/new_hero_context.py excel_rNNN --report reports/<目录>` 摘要失败项，再只读失败调用链和相关源类；不要重读整个架构或全英雄文件。修复后助手自跑短定向与有界长审计。
