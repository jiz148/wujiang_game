## 1. 本次失败原因总结

### 已能确认的原因

1. **共同接口的调用不一致。** AI候选生成有738条 `DamageContext` 不接受 `ignore_targeting_restrictions` 的异常，涉及龙骑和抹杀的使徒；163条缺少必需的 `is_skill`，涉及甲虫装甲骑士和魔战士。这两类调用错误占911条候选生成错误中的901条。说明静态语法检查没有验证实际构造参数，也没有证明AI预演可运行。最终应修改哪个调用点及如何保持规则，仍需对照设计和接口职责确认。
2. **测试自身存在错误。** 回归包括伤害上下文缺必需参数、过时函数调用、抽象 `Skill` 直接实例化、缺导入/不存在属性、使用不具备该技能的武将等错误。这类结果必须修测试场景或调用，不应反向改变武将规则。
3. **统一测试暴露了静态检查无法证明的行为。** 第一轮各批直到最后统一测试前只做静态检查；接口构造、真实行动窗口、AI候选执行和跨武将状态交互的运行时问题在本次动态阶段集中暴露。检查修改完成、测试已编写和动态验收通过是三个不同状态。

## 2. 未来实现武将时需要注意

| 注意事项 | 在实现中怎么落实 | 本次依据与置信度 |
| --- | --- | --- |
| 源规则与设计先锁定 | 从原文、通用规则和保存答案确定含义；再检查实现、AI和测试；推断记录理由和置信度 | 既有项目要求；失败不能成为新的规则来源 |
| 共同接口变更必须检查所有调用方 | 核查英雄、通用AI、预演、房间恢复及测试调用；关键构造走真实路径；不要把仅用于目标校验的参数随意传入伤害对象 | 两类参数异常已确认；具体修法待确认 |
| AI预演与正式执行遵守同一行为契约 | 使用相同的范围、攻击形状、目标资格、资源、冷却和合法窗口；预演可回滚且不得额外抽随机数 | 本次大量候选与执行不一致，需要逐条溯源 |
| 分清声明信息和结算时状态 | 明确哪些坐标、攻值、形状在声明时冻结，哪些受体和防御在结算时读取；连锁后不要重新解释已合法声明的动作 | 吸魔/普攻范围异常提示；最终边界由源规则决定 |
| 每项成本与额度要有明确归属 | 标明声明时还是结算时付费、一次动作还是逐命中、普通攻击/额外攻击/反击是否独立；取消和未命中的消耗也由设计定义 | 攻击额度与预付相关异常提示；不是所有取消都退款 |
| 生命周期使用正确时钟 | 区分全局英雄回合、本人开始/结束、应用当轮是否计时；状态解除不能清除另一来源仍维持的限制 | 到期和窗口失败提示；生产错误与测试夹具待区分 |
| 特殊身体与复制不走简化捷径 | 分清真英雄、召唤/克隆、技能提供者、骑手/坐骑和实际受体；多格去重，保留小数，不按显示名称归属日志 | 黑豹技能身份异常已观察；骑乘/多格断言待核对 |
| 验证实际结果，覆盖异常路径 | 检查伤害公式、免疫/破魔/护盾、空目标、取消、死亡/复活、选择暂停与恢复；测试场景先满足技能和行动资格 | 本次运行时错误与无效夹具均存在 |
| AI使用次数不是验收标准 | 比较有效候选、未采用理由、真实收益、友损、有限资源和后续机会；无收益时不用技能可能合理 | 审计有“无有效影响”和“有候选未使用”，须分别判断 |
| 前后端与房间是完整能力的一部分 | 声明参数、预览、点击选取、权限/超时、恢复和日志共同检查；新选择流程不能只在直接调用里可用 | 前端与房间回归已出现，最终责任待归因 |
| 静态与动态验证分别记录 | 语法/引用检查只证明相应静态性质；动态未运行或失败就保留待验收状态，按用户安排统一运行 | 本次已经证明静态通过不足以保证动态通过 |

这些是实现检查方向，不替代每名武将的源规则。只有复现、修正和验证完成的条目才能记录为已确认根因或可复用的具体修法。

## 4. 修复时持续填写的记录

每次具体修改同步更新对应记录，不等第二轮结束才补写。根因尚未确定时只写观察和假设；修复完成但动态验证未做时保留“待动态验证”。建议状态：待归因 → 已确认 → 已修复/待动态验证 → 已验证关闭；也可结案为正常观察、覆盖不足或转独立系统，但须有依据。

### 单项记录模板

- **编号与状态：**SR2-xxx；记录/更新时间。
- **现象与证据：**回归具名用例/行号，或seed、step、演员、原动作来源、实际受体、动作和结果；归档路径。
- **设计依据：**源表/保存答案/通用规则/锁定设计条目；预期行为；有歧义时记录推断、证据和置信度。
- **归因：**分类、真正责任机制、已确认根因与尚待确认部分；关联或重复记录编号。
- **修正：**改了什么、为什么，涉及英雄、通用引擎、AI、前端/房间、测试和文档的位置。
- **影响面：**直接受影响英雄与共享调用方；是否需要检查其他身体、状态、行动窗口或恢复路径。
- **验证：**新增/调整的必要场景；静态结果；动态是否运行、结果与新报告；未覆盖风险。
- **未来实现经验：**适用条件、可复用机制、需要避免的具体做法；验证后同步到本文件经验表及项目技能索引。
- **关闭依据：**为何可关闭；覆盖不足和独立系统问题如何处置；未验证时不得标为关闭。
