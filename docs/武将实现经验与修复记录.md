## 1. 本次失败原因总结

### 已能确认的原因

1. **共同接口的调用不一致。** AI候选生成有738条 `DamageContext` 不接受 `ignore_targeting_restrictions` 的异常，涉及龙骑和抹杀的使徒；163条缺少必需的 `is_skill`，涉及甲虫装甲骑士和魔战士。这两类调用错误占911条候选生成错误中的901条。说明静态语法检查没有验证实际构造参数，也没有证明AI预演可运行。最终应修改哪个调用点及如何保持规则，仍需对照设计和接口职责确认。
2. **测试自身存在错误。** 回归包括伤害上下文缺必需参数、过时函数调用、抽象 `Skill` 直接实例化、缺导入/不存在属性、使用不具备该技能的武将等错误。这类结果必须修测试场景或调用，不应反向改变武将规则。
3. **统一测试暴露了静态检查无法证明的行为。** 第一轮各批直到最后统一测试前只做静态检查；接口构造、真实行动窗口、AI候选执行和跨武将状态交互的运行时问题在本次动态阶段集中暴露。检查修改完成、测试已编写和动态验收通过是三个不同状态。

## 4. 修复时持续填写的记录

每次具体修改同步更新对应记录，不等第二轮结束才补写。根因尚未确定时只写观察和假设；修复完成但动态验证未做时保留“待动态验证”。建议状态：待归因 → 已确认 → 已修复/待动态验证 → 已验证关闭；也可结案为正常观察、覆盖不足或转独立系统，但须有依据。

### 单项记录模板

- **编号与状态：**SR2-xxx；记录/更新时间。
- **现象与证据：**回归具名用例/行号，或seed、step、演员、原动作来源、实际受体、动作和结果；归档路径。
- **设计依据：**源表/保存答案/通用规则/锁定设计条目；预期行为；有歧义时记录推断、证据和置信度。
- **归因：**分类、真正责任机制、已确认根因与尚待确认部分；关联或重复记录编号。
- **修正：**改了什么、为什么，涉及英雄、通用引擎、AI、前端/房间、测试和文档的位置。
- **影响面：**直接受影响英雄与共享调用方；是否需要检查其他身体、状态、行动窗口或恢复路径。
- **验证：**新增/调整的必要场景；静态结果；动态是否运行、结果与新报告；未覆盖风险。
- **未来实现经验：**适用条件、可复用机制、需要避免的具体做法；验证后同步到本文件经验表及项目技能索引。
- **关闭依据：**为何可关闭；覆盖不足和独立系统问题如何处置；未验证时不得标为关闭。
