## 第三批：精确缓存与隔离的 CPU 并行

2026-10-18 用户明确授权实施空间换时间和 CPU 多进程，仍要求完整 AI 行动逻辑不变。

### 缓存边界

- `engine/geometry.py` 缓存只含整数的身体偏移、邻接格及精确范围格。键包含棋盘尺寸、位置、完整身体偏移和距离；范围格保持逐身体格判断及行优先顺序。缓存均有条数上限，超过 4096 格的范围查询不保留大结果。调用方得到新列表，不能污染缓存。
- `Battle.cells_within_distance` 是共用范围查询，远程矩形生成和原有区域中心选择使用它。范围值在一次只读枚举开始时读取，结果仍与原来的逐格验证一致，不改范围或候选。
- `rooms/ai_acceleration.py` 为一次详细 AI 选择建立独立缓存，针对共享 `reviewed_r17_position_value`。键使用实际序列化战斗、Python 随机状态和弱引用绑定信息，再按演员/受评单位区分；不是位置/血量等不完整摘要，也不按哈希近似认定相等。
- 只有计算前后快照相等、随机状态相等、两个 ID 序列都未推进的有限标量结果可以复用。会消耗编号、改变随机状态、修改战场、不能序列化或快照超过 1 MiB 的查询保留原计算；非有限数值不缓存。不能序列化时本次选择停止尝试缓存，避免反复付出失败开销。
- 每次选择结束释放缓存，最多保留 32 个状态，按序列化体积及固定开销设置约 16 MiB 的状态预算。不会跨真实动作把旧位置收益带到新局面。

### CPU 并行边界

- 不并发修改真实战场，不把一次技能结算拆到共享线程中。对不少于 12 个单位的共享完整效果评估，可把当前状态下互相独立的位置收益查询交给隔离子进程预计算；调用原有收益函数和伤害探针。
- 默认共用最多 4 个子进程（2026-10-18用户要求由2调至4），并受可用 CPU 数量减一的限制；工作进程不递归建池。小场景、单核/双核不足条件及关闭并行时继续串行缓存。`WUJIANG_AI_WORKERS=0` 或 `1` 禁用进程，`2`～`4` 设置上限。已有显式环境设置继续优先；修改默认值须重启服务器加载。自走棋快速模拟不提交此类可选预计算；其他模式的每批等待最多2秒，超时或进程故障后按原评分函数串行完成并停用故障进程池。
- 子进程必须先通过快照加载/重存一致性检查，再从相同随机状态和 ID 起点计算；只返回通过无副作用检查的标量，不能回写战场。主进程仍按原单位顺序读取收益、累计分数及选择动作，不按哪个任务先完成决定行动。
- 状态无法完整转移、计算产生副作用或进程失败时，相关查询仍在主进程按原逻辑计算，不能跳过候选或改用近似评分。支持不了的状态可能只有串行缓存收益，也可能完全走原路径；报告中的 `worker_values` 才代表实际接受的子进程结果。
- 两个 ID 发生器改为保持相同整数序列、支持无消耗查看及独立副本的线程安全容器。正式动作仍共享原有编号顺序，不用分进程另编号的方式改变后续战斗。对照工具同时比较最终编号位置。
- `run.py` 延迟导入服务器组合入口，避免 Windows spawn 加载入口时建立重复服务器服务。进程池只在真正需要时建立，首个并行样本可能有启动成本；计时保留原始样本，不能隐藏冷启动。

这次并行的是完整 AI 内部的独立收益预计算，自走棋配对推进、真实战斗动作和连锁仍保持既有顺序。它不是“同时让多场战斗任意消耗全局随机数”，也没有 GPU 路径。
