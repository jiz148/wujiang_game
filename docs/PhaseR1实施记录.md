# 救援 Phase R1 实施记录

> 状态：已结束（项目负责人于 2026-08-16 确认）  
> 日期：2026-08-16  
> 下一阶段：R2“地图优先 UI 重构”（已进入）

## 1. R1 解决的问题

普通战略首局把长期战役、完整官职、世界危机、圣物和大量城市后台同时交给新玩家，第一分钟缺少清晰的高后果选择，战斗结果与战役结局又藏得太深。R1 把首局收束为一条 5 城、6 月、固定主公、单人对 AI 的紧凑战役，不新增世界危机、圣物、英雄、科技或建筑内容。

## 2. 已完成范围

- R1.1：一键创建并自动锁定快速战役，固定玩家主公，空席由 AI 接管。
- R1.2：第一月必须从稳民心、城邦外交、整军备战中三选一，效果即时写入真实状态。
- R1.3：开局后只突出治理、外交、军事三项同规则动作；可一键排入职位委托、中立外交或主公亲征。快速地图保证第二月前存在合法扩张窗口，结算后的最近战果直接显示在三项建议之前。
- R1.4：六月评议直接显示排名、分项与完整复盘，并替换失效的月度推荐和职位军令；继续沙盒保留评议并重新开放月份，归档冻结只读，再开一局回到全新的第一月国策。快速战役列表明确显示单人对 AI，不再把 AI 职位计作真人初始玩家。

## 3. 完整首局验收

自动化行为场景覆盖：一键开始 → 整军国策 → 2 军令主公亲征 → 战果反馈 → 推进至六月评议 → 结算状态拒绝重复推进 → 保留评议继续沙盒 → 第二局推进并归档只读 → 第三局从第一月重新开始。另一条错误路径验证第一月未选国策不能推进、国策不能重复领取，错误后合法流程仍可继续。

本地浏览器以桌面和 375×812 手机走完相同关键链。六月评议按钮可直接操作；手机页面宽度 360px、滚动宽度 360px，没有页面级横向溢出，“再开一局”按钮高度 45px。浏览器真实发现并修复了结算状态被误当作“等待初始玩家”、归档被误当作“未锁定大厅”、AI 职位被显示为真人初始玩家，以及结算后仍展示整套职位军令的问题。

最终验证结果：策略与前端定向测试通过，JavaScript 语法检查与 Python 编译检查通过；完整回归共 756 项通过，8 项因环境条件跳过，0 项失败。
