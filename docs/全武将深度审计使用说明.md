# 全武将深度审计使用说明

> 2026-09-06当前流程：用户要求先连续改完所有已开发武将和AI，最后统一测试。中途无需执行下面的当前批次命令，也不等待逐批复测。全部73名检查修改完成后运行 `python detail_test_all_wujiangs.py`。以下 `--current` 和 `--summarize-only` 保留为可选诊断用法。

## 当前审查批次：日常复测命令

每完成当前一名或一小批武将的修改，在项目根目录运行：

```powershell
python detail_test_all_wujiangs.py --current
```

该模式从 `docs/武将符合性审查.json` 的 `current_hero_codes` 读取当前审查批次。当前为 `excel_r126`（太阳神）、`excel_r291`（机甲忍者。赤）、`excel_r356`（强袭犀牛）。它运行完整常规测试，以及当前批次每武将 10 场深度 AI 对局，以检查武将与通用 AI 的改动。当前结果目录是 `reports/current-hero-deep-audit/excel_r126--excel_r291--excel_r356`。

每次开始审查下一批武将时，开发代理必须先更新 `current_hero_codes`，所以用户不需要记武将代码，也不需要改命令。默认不会复用旧对局，确保代码修改后的结果是新生成的；只有中途被打断、代码又没有变化时，才在命令末尾加 `--resume` 续跑。

## 精简复核入口

当前批次命令完成后自动生成 `review_packet.md` 和 `review_packet.json`。先读 Markdown：全部常规测试失败标题及原日志行号、全量 findings 分类统计（包括普通观察）、每名武将的观察与覆盖缺口、代码改动路径。JSON 列出每一场 trace 的位置与记录数；原始日志和逐将完整报告仍保留，所有发现及关键决策仍需对照锁定设计基线复核。摘要不会证明所有设计差异已被发现，也不会把未覆盖情况当作通过。

只想整理上一次结果，不重跑测试，可运行：

```powershell
python detail_test_all_wujiangs.py --current --summarize-only
```

它会读取完整 findings 与全部已列出的 trace，报告缺失、损坏和数量不符；不会执行测试、推进对局或修改验收状态。旧结果始终标记为旧结果，不能据此接受后来修改的代码。没有已有完整报告时会报错，不会悄悄开始测试。

`code_changes/staged.patch` 和 `unstaged.patch` 分别保存暂存与未暂存的完整 Git 差异，包含二进制补丁，避免两部分相互抵消后漏看。新增未跟踪文件列出路径，按需读取原文件；遵循 Git 忽略规则，并排除 `outputs/`、`reports/` 生成物。参照点是 Git HEAD/暂存区，**不是上次验收版本**，不包含已提交历史，也不保证测试期间工作区未改变。共享引擎、AI、前端改动需扩大代码复核范围；完整常规测试照常执行。

## 全武将：阶段性总检命令

在项目根目录的 PowerShell 或命令行中运行这个短命令即可：

```powershell
python detail_test_all_wujiangs.py
```

它默认等价于以下完整命令：

```powershell
python tools/audit_all_heroes.py --matches-per-hero 10 --max-steps 500 --seed 20260831 --out reports/all-hero-deep-audit/current
```

短命令也接受相同参数；例如只测试指定武将时可以运行 `python detail_test_all_wujiangs.py --targets excel_r126,excel_r142 --out reports/all-hero-deep-audit/focused --resume`。

该命令首先执行 `tests` 目录中的完整常规测试，把规则单测、简单回合测试、玩家行为测试和审计组件测试统一记录下来；随后测试当前公开测试池里的全部武将，每名武将进行 10 场不同队友、对手和种子的 2v2 AI 对局。常规测试即使出现失败，也不会阻止后面的逐武将审计。`--resume` 会复用已经完整写出的单场对局结果，所以中途停止后可以用同一条命令继续。

开发代理不再单独运行任何会推进回合或模拟对局的测试。语法等静态检查由开发代理完成，所有动态测试统一由用户通过当前批次命令或阶段性全武将命令执行。

本工具不会自动把武将判为“设计正确”。它负责记录证据、暴露覆盖缺口并排列人工复核顺序；最终判断仍需把对局证据与《武将实现问题清单.xlsx》中的“武将设计思想”逐项比较。

## 完成后先看什么

运行完成后，当前批次模式的目录前缀是 `reports/current-hero-deep-audit/<批次代码>`，全武将模式的目录前缀是 `reports/all-hero-deep-audit/current`。在对应目录中优先打开：

先打开 `review_packet.md`，需要细节时再按索引读取以下完整材料：

1. `regression_tests.log`：完整常规测试原始输出，包括每个失败和错误的堆栈。
2. `regression_tests.json`：常规测试数量、退出状态、耗时和总体结果。
3. `review_queue.md`：按 P0～P3 排列的逐武将人工复核队列。
4. `hero_reviews/<武将代码>.md`：该武将的设计思想、动作覆盖、未使用技能、关键日志缺口、生命/魔力/移动统计及每场报告入口。
5. `suspected_defects.jsonl`：动作错误、AI 候选异常等高信号问题。
6. 单场目录中的 `battle_report.md`、`trace.jsonl` 和 `findings.md`：逐步动作、候选判断、状态变化与具体日志。

## 会记录的具体反馈

- 每场阵容、种子、胜方、步数、是否达到上限。
- 完整常规测试的成功、失败、错误、跳过信息与具体堆栈；简单回合测试包含在这里，不再另行执行。
- 每个武将及其相关召唤物的移动、普攻、技能和连锁反应次数。
- 每项主动/随时技能是否曾被 AI 使用，以及设计要求观察的动作和日志是否出现。
- 每步 AI 选择理由、候选分数、提交参数、执行成功与否、新增战斗日志和单位状态差异。
- 生命、魔力、位移、死亡、入场和离场的累计变化。
- 非法动作、候选生成缺口、候选被意外过滤、模拟卡住和步数上限等 findings。
- 违反“一次声明动作只触发一次”的重复反制；目前猫叔会为每次实际反制记录带动作解析 token 的结构化规则事件，同一 token 重复出现会成为高信号 `duplicate_once_per_action_trigger`，不同嵌套声明动作不会误报。
- 已有结构化设计思想的武将会在报告中直接显示“设计意图—AI原则—预期信号—风险反模式”对照；缺少设计基线的旧武将会明确进入补写队列。

## 只测试指定武将

日常只测当前审查批次时优先使用：

```powershell
python detail_test_all_wujiangs.py --current
```

需要临时指定不属于当前批次的一名或一小批武将时才使用：

```powershell
python tools/audit_all_heroes.py --targets excel_r126,excel_r142 --matches-per-hero 10 --max-steps 500 --seed 20260831 --out reports/all-hero-deep-audit/focused --resume
```

不要删除或覆盖仍需复核的报告目录；修复后使用新的输出目录重跑，便于前后比较。
